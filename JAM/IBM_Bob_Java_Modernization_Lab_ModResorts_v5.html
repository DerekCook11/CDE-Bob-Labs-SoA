Workshop Overview

Modernize ModResorts Without Re-Architecting It

You are given the legacy application modresorts-twas-j8.zip.

The goal is to use IBM Bob to modernize the supporting Java/WebSphere stack while preserving the application as a monolith.

BEFORE ModResorts Monolith ├─ Java 8 ├─ Java EE ├─ Traditional WebSphere APIs ├─ was_public dependency └─ Traditional WebSphere assumptions ↓ AFTER ModResorts Monolith ├─ Java 17 ├─ Standard Java / Servlet / JNDI APIs ├─ No required was_public dependency ├─ Open Liberty └─ Existing application behavior preserved
Workshop principle: Same application, modern foundation.
Token-efficient validation: this workshop uses only four meaningful checkpoints—environment, modernization, build/quality, and runtime—and generates only one final HTML report.
Lab Objectives

What Participants Will Do

  • Analyze the legacy application and architecture.
  • Identify WebSphere-specific APIs and dependencies.
  • Create and review a modernization plan.
  • Modernize the application from Java 8 to Java 17.
  • Remove unnecessary traditional WebSphere dependencies.
  • Build the application successfully as a WAR.
  • Create automated tests and measure code coverage.
  • Run the application locally on Open Liberty.
  • Verify /resorts still works.
  • Generate modernization documentation.
