ModResorts Application Modernization Report

Transformation from Traditional WebSphere (Java 8) to Open Liberty (Java 17)

Executive Summary

Modernization Overview & Metrics

The legacy ModResorts application has been modernized from Java 8 running on traditional WebSphere Application Server (tWAS) to Java 17 running on Open Liberty. The application remains an identical monolithic WAR artifact, retaining its complete business functionality, HTML/JSP user interface, and javax.* Servlet namespace without unnecessary architectural sprawl.

Code Refactoring

Key Code Refactoring Examples

1. Security & Logout: WSSecurityHelper → Standard Servlet API

Before (tWAS):

// Legacy WebSphere proprietary security revocation
com.ibm.websphere.security.WSSecurityHelper.revokeSSOCookies(request, response);
com.ibm.websphere.security.auth.WSSubject.getCallerPrincipal();

After (Open Liberty / Standard Servlet 3.1):

// Standard Portable Java EE Servlet API
HttpSession session = request.getSession(false);
if (session != null) {
    session.invalidate();
}
request.logout();

2. Response Escaping: ResponseUtils → Portable Sanitizer

Before (tWAS):

// WebSphere proprietary response utility
String newStr = com.ibm.websphere.servlet.response.ResponseUtils.filter(originalStr);

After (Standard Java):

// Self-contained portable HTML encoder
private static String encodeHtml(String input) {
    if (input == null) return "";
    StringBuilder sb = new StringBuilder();
    for (char c : input.toCharArray()) {
        switch (c) {
            case '&': sb.append("&"); break;
            case '<': sb.append("<"); break;
            case '>': sb.append(">"); break;
            case '"': sb.append("""); break;
            case '\'': sb.append("'"); break;
            default: sb.append(c);
        }
    }
    return sb.toString();
}

3. Runtime Server Identification: ServerName → Standard JMX

Before (tWAS):

String serverEnv = com.ibm.websphere.runtime.ServerName.getDisplayName();

After (Standard Java):

String serverEnv = ManagementFactory.getRuntimeMXBean().getName();

4. JNDI Context: WsnInitialContextFactory → Standard JNDI

Before (tWAS):

Hashtable<String, String> env = new Hashtable<>();
env.put(Context.INITIAL_CONTEXT_FACTORY, "com.ibm.websphere.naming.WsnInitialContextFactory");
InitialContext ctx = new InitialContext(env);

After (Standard InitialContext):

InitialContext ctx = new InitialContext();
Validation & Remediation

Runtime Issues Discovered & Resolved

Issue Area Symptom / Discovery Root Cause Resolution
Missing Frontend Asset Browser console threw Pikaday is not defined; 404 on lib/pikaday.js. Pikaday JavaScript library was referenced in WebContent/index.html but absent from the legacy repository. Included standalone Pikaday v1.8.2 JavaScript into WebContent/lib/pikaday.js.
Missing Runtime Library (Gson) NoClassDefFoundError: com.google.code.gson.Gson on weather/availability REST calls. Gson was historically provided by tWAS shared libraries and was not packaged in the WAR. Added com.google.code.gson:gson:2.10.1 with standard compile scope so it is bundled in WEB-INF/lib.
Surefire / JaCoCo argLine Surefire JVM startup failure passing literal @{argLine} or conflicts in dev mode. Missing dedicated late-binding property definition for JaCoCo execution argument line. Defined <jacocoArgLine></jacocoArgLine> and configured <propertyName>jacocoArgLine</propertyName> in JaCoCo plugin.
Stale Liberty Port Binding CWWKO0221E: The socket bind did not succeed for host * and port 9080. Address already in use. A prior background JVM process had retained port 9080. Identified and terminated the stale process ID, installed Open Liberty features (servlet-3.1, jsp-2.3, etc.), and deployed the clean WAR.

Scope & Guardrails

What Did Not Change

To prevent scope creep and maintain architectural stability, the following architectural aspects were intentionally kept identical:
  • Monolithic Architecture: The application remains a monolith packaged as a single WAR.
  • Business Logic & Functionality: All reservation, weather lookups, availability rules, and filters operate with identical business logic.
  • Frontend Technology: The existing JSP and HTML/CSS/Vanilla JS UI was preserved; no React or single-page framework was introduced.
  • Packaging Standard: The build produces standard Java Web Application Archive (modresorts-2.0.0.war).
  • Database Schema & State: No database migration was performed.
  • No Microservices: No service decomposition or microservice boundaries were introduced.
  • No Kubernetes / OpenShift: Deployed directly on lightweight local Open Liberty runtime.
  • No CI/CD Pipeline: Built and validated using standard local Maven CLI tools.
  • Java EE Namespace Preserved: Application APIs retain javax.* / javax.servlet.* (no Jakarta EE 9/10 namespace migration).
Risk Assessment

Remaining Warnings and Future Considerations

  • Java Security Manager Deprecation: com.acme.modres.security.Service invokes System.getSecurityManager(), which produces a standard Java 17 compile warning (marked for removal in future Java releases). This has zero impact on Java 17 Open Liberty operation.
  • Offline Weather API: The application correctly falls back to embedded city JSON data when external Weather Underground API keys are absent.
