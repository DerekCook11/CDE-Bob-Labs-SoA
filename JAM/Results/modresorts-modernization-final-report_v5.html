1. Architecture — Before vs. After

Before (WAS Traditional)

  • Java 8 (javac -source 1.8)
  • WebSphere Application Server 9.0
  • WAS APIs: WSSecurityHelper, ResponseUtils, ServerName, WsnInitialContextFactory
  • was_public:9.0.0 compile dependency
  • WAS JNDI (iiop:// bootstrap)
  • WAR, ibm-web-ext.xml context root
  • Missing lib/pikaday.js (ReferenceError)
  • Pikaday date range locked to 2020
  • No test harness, no JaCoCo

After (Open Liberty)

  • Java 17 (javac --release 17)
  • Open Liberty 22.0.0.13 (webProfile8)
  • Standard Servlet 3.0/4.0 APIs only
  • was_public removed entirely
  • Standard JNDI: new InitialContext()
  • WAR, context root in server.xml
  • lib/pikaday.js added (42 KB, MIT)
  • Pikaday date range: currentYear + 2
  • 24 JUnit 5 tests, JaCoCo ≥80% enforced

BeforeAfter

    ResponseUtils.encodeDataString(newStr);
 
private String encodeForHtml(String s) {
    return s.replace("&","&amp;")
            .replace("<","&lt;")
            .replace(">","&gt;")
            .replace("\"","&quot;")
            .replace("'","&#x27;");

12. Runtime Issues Discovered and Resolved

12.1 Missing lib/pikaday.js (Critical Frontend)

Problem: WebContent/lib/ was absent. index.html referenced <script src="lib/pikaday.js">, causing Uncaught ReferenceError: Pikaday is not defined. Both date pickers non-functional.

Resolution: Added WebContent/lib/pikaday.js (Pikaday 1.8.2, MIT, 42 KB). Served at HTTP 200 from Liberty.

12.2 Pikaday Date Range Locked to 2020

Problem: maxDate: new Date(2020, 12, 31) and yearRange: [2000, 2020] prevented all date selection in 2026.

Resolution: Changed to new Date(_currentYear + 2, 11, 31) and yearRange: [_currentYear, _currentYear + 2].

12.3 Gson Missing at Runtime (Potential)

Problem: JsonInputStream uses Gson. Liberty does not provide it. Had scope been provided, runtime would throw ClassNotFoundException: com.google.gson.Gson.

Resolution: Confirmed gson:2.10.1 scope is compile; 283 KB JAR lands in WEB-INF/lib.

12.4 Maven Surefire / JaCoCo argLine Late-Binding

Problem: <argLine>${jacocoArgLine}</argLine> resolved the property value before prepare-agent ran. The forked test JVM started without -javaagent; jacoco.exec was never written. JaCoCo skipped coverage check with "missing execution data file".

Resolution: Changed to @{jacocoArgLine} (Surefire 3.x late-binding). Added empty default property so mvn liberty:dev (which skips prepare-agent) does not see a literal @{}.

12.5 Mockito mockConstruction<URL> → ByteBuddy Classloader Corruption

Problem: 5/24 tests failed with NoClassDefFoundError: com/acme/modres/exception/ExceptionHandler when run as a suite but passed in isolation. Mockito's mockConstruction<URL> installs a ByteBuddy-managed classloader for the try-with-resources scope. When ExceptionHandler was first resolved inside that scope (during API-key success tests), the JVM permanently poisoned the class for that loader. All subsequent loads threw NoClassDefFoundError.

Resolution: Extracted HTTP connection creation into a protected openConnection(String url) seam on WeatherServlet. Test subclass FakeKeyServlet overrides the method and returns a pre-configured mock — no ByteBuddy, no classloader pollution. All 24 tests pass in any order.

12.6 Liberty Kernel-Only Runtime Missing Features

Problem: Default liberty-maven-plugin downloaded openliberty-kernel (zero features). Every feature in server.xml reported CWWKF0001E: feature not found. WAR could not deploy.

Resolution: Added <runtimeArtifact> pointing to io.openliberty:openliberty-webProfile8:22.0.0.13, which includes all required features.

12.7 Feature Version Mismatch in server.xml

Problem: server.xml requested cdi-1.2, servlet-3.1, jdbc-4.1 — versions absent from webProfile8-22.0.0.13 (which ships cdi-2.0, servlet-4.0, jdbc-4.2).

Resolution: Updated feature names to match the installed runtime. App code targets Servlet 3.1 API, fully compatible with the Servlet 4.0 feature.

12.8 ops.json Invalid MBean Impact Value

Problem: ops.json contained "impact": 10. Java 17's MBeanOperationInfo only accepts 0–3; value 10 caused IllegalArgumentException during MBean registration.

Resolution: Changed "impact": 10 → "impact": 1 (ACTION).

Summary

The ModResorts monolith has been successfully modernized from WebSphere Application Server traditional (Java 8) to Open Liberty (Java 17). All four WebSphere proprietary API usages are replaced with standard Servlet and Java SE equivalents. The WAR structure, frontend, and all business functionality are preserved unchanged. The application deploys cleanly on Open Liberty 22.0.0.13, serves all HTTP endpoints with 200, and passes a 24-test JUnit 5 suite with 82.7% LINE coverage on the primary servlet — exceeding the 80% threshold enforced automatically at mvn clean verify.
