Step 0

Prepare the VM

Lets download the Legacy App

Legacy App: modresorts-twas-j8.zip
Download Legacy App Code 
unzip modresorts-twas-j8.zip

IBM Bob is assumed to already be installed. Run the provided prerequisite script to prepare the supporting RHEL environment.

Prerequisite script: modresorts-lab-prereq.sh
Download prerequisite script 
chmod +x modresorts-lab-prereq.sh
./modresorts-lab-prereq.sh

The script checks or installs:

  • Java 17 JDK
  • Maven 3.8.6+ (3.9.16 recommended)
  • curl, unzip, git, tar, gzip
  • Maven Central connectivity
  • Port 9080 availability
  • Disk space
Checkpoint 1 — Environment Ready
Proceed only when the script reports FAIL: 0.
Step 1

Analyze & Plan

Open the extracted modresorts-twas-j8 project in Bob.

Prompt to Bob

Analyze this legacy Java application and create a modernization plan.

Identify:
- Current architecture and Java version
- Major application components
- Maven dependencies
- Traditional WebSphere-specific APIs and dependencies
- Deprecated APIs
- Technical debt and compatibility risks

Modernization requirements:
- Keep the application as a monolith
- Migrate Java 8 to Java 17
- Replace traditional WebSphere-specific APIs with standard Java, Servlet, or JNDI alternatives where possible
- Remove obsolete WebSphere dependencies such as was_public when no longer required
- Keep the existing JSP/HTML frontend
- Preserve existing business functionality
- Continue packaging as a WAR
- Run locally on Open Liberty

Do not introduce:
- Microservices
- Kubernetes or OpenShift
- React
- Database migration
- CI/CD

Provide a concise modernization plan before making changes.
Expected findings: Bob should identify WebSphere-specific usage such as WSSecurityHelper, ResponseUtils, ServerName, WsnInitialContextFactory, and the was_public Maven dependency.
Step 2

Modernize & Build

Prompt to Bob

Implement the approved modernization plan.

Perform the required code and configuration changes.

Then run:

mvn clean package

Continue fixing compilation, dependency, or configuration issues until:

- Java target is 17
- Traditional WebSphere-specific APIs have been removed or replaced as planned
- was_public is removed if no longer required
- WAR is generated
- BUILD SUCCESS

At completion, briefly report:
- Files changed
- Key APIs/dependencies removed or replaced
- WAR location
- Remaining warnings
Checkpoint 2 — Modernization Complete
Confirm Java 17, the intended WebSphere API replacements, removal of was_public if no longer needed, and a successful WAR build.
Typical changes Bob may make
  • LogoutServlet: WSSecurityHelper → standard servlet logout/session invalidation.
  • UpperServlet: ResponseUtils → portable HTML escaping.
  • WeatherServlet: ServerName → standard Java runtime properties.
  • WeatherServlet: WsnInitialContextFactory → standard InitialContext.
  • pom.xml: Java 8 → Java 17 and removal of was_public where no longer needed.
Step 3

Test & Quality

Prompt to Bob

Create and run an automated test harness for WeatherServlet.

Use:
- JUnit 5
- Mockito
- Spring Test mock servlet objects
- JaCoCo

Do not use live external weather services.

Test meaningful normal, edge, and error scenarios.

Run:

mvn clean verify

Continue fixing issues and adding meaningful tests until:

- All tests pass
- Failures = 0
- Errors = 0
- WeatherServlet line coverage >= 80%
- WAR is generated
- BUILD SUCCESS

Do not disable tests or lower the coverage threshold.

Report only:
- Test count
- Failures/errors
- Coverage percentage
- Final build status
Checkpoint 3 — Build & Quality
Success requires all tests passing, zero failures/errors, WeatherServlet line coverage ≥80%, WAR generated, and BUILD SUCCESS.

JaCoCo report:

target/site/jacoco/index.html
Step 4

Run, Verify & Document

Prompt to Bob

Run the modernized application locally on Open Liberty.

Use the existing Liberty server.xml where appropriate.

Start Liberty with:

mvn liberty:dev

Verify:

curl -I http://localhost:9080/resorts/

Success criteria:
- Liberty starts successfully
- ModResorts deploys successfully
- /resorts returns HTTP 200
- The application page loads successfully

After verification, create one final interactive HTML modernization report named:

modresorts-modernization-final-report.html

Include:
- Original architecture
- Modernized architecture
- Java 8 → Java 17
- WebSphere APIs/dependencies removed or replaced
- Files changed
- Maven changes
- Build result
- Test result
- Coverage result
- Liberty deployment result
- HTTP verification
- Remaining warnings or risks
- Before vs. after architecture diagram

Also include a clear Before vs. After Change Matrix covering:
- Java version
- Runtime
- WebSphere-specific APIs
- Maven dependencies
- JNDI usage
- WAR packaging
- Frontend
- Application architecture

For each important modernization change, show a concise before/after code example where applicable, including:
- WSSecurityHelper → standard Servlet logout/session handling
- ResponseUtils → portable HTML escaping
- ServerName → standard Java runtime properties
- WsnInitialContextFactory → standard InitialContext

Add a section titled "What Did Not Change" and explicitly state:
- The application remains a monolith
- Existing business functionality is preserved
- JSP/HTML frontend remains
- WAR packaging remains
- No database migration was performed
- No microservices were introduced
- No Kubernetes or OpenShift was introduced
- No React migration was performed
- No CI/CD implementation was performed

Keep the report concise, evidence-based, and focused on what actually changed versus what stayed the same.
Checkpoint 4 — Runtime Verification
Success requires Liberty startup, successful ModResorts deployment, and HTTP 200 from /resorts.
Final Lab Artifact: modresorts-modernization-final-report.html
The report must clearly show the before state, after state, files changed, key code/API replacements, and what remained unchanged.
