1. Executive Summary

The ISS Travel App has been successfully migrated from IBM WebSphere Application Server 9 / Java EE 7 / Java 8 to Open Liberty 26.0.0.9 / Java EE 8 (Servlet 4.0) / Java 17.

The migration eliminated all proprietary IBM/WebSphere runtime dependencies, removed the EAR packaging layer, deleted three IBM-specific deployment descriptors, and replaced three WebSphere API wrapper classes with standard Servlet 4.0 equivalents. All four REST endpoints, the sample travel data, the in-memory repository, and the browser UI remain fully functional and behaviorally identical to the legacy version.

The build now succeeds on a clean Java 17 / Maven 3.9 environment with no WAS_HOME environment variable and no IBM software installed. Open Liberty 26.0.0.9 is downloaded automatically by the Liberty Maven plugin at build time.

10. Remaining Risks & Follow-up Items

ItemSeverityNotes
In-memory data storeBy designData resets on server restart. This is intentional per the lab specification. Production use would require a persistent datastore (e.g. PostgreSQL via JDBC or JPA with jpa-2.2 Liberty feature).
openliberty-runtime:RELEASE versionLowUsing RELEASE resolves the latest Liberty at build time, which may change between builds. Pin to 26.0.0.9 (or a specific release) in pom.xml for reproducible CI/CD pipelines.
JUnit 4 test frameworkLowTravelRepositoryTest uses JUnit 4.13.2 which runs without issues on Java 17. Migrating to JUnit 5 (Jupiter) is optional but aligns with current Open Liberty and Maven Surefire guidance.
Hand-rolled JSON parser in JsonUtilLowThe regex-based readString() handles flat string fields only. It does not support nested objects, arrays, or numeric JSON values. Sufficient for the current API shape; a production service should use Jackson or JSON-B (jsonb-1.0 Liberty feature).
No authentication or authorisationLowThe legacy travel-user security role was declared but never enforced by a URL constraint, so its removal has no functional impact. If authentication is required, Liberty's appSecurity-3.0 feature and a <basicRegistry> or LDAP registry provide a standard path.
HTTP only (no TLS in development)LowPort 9443 is declared in server.xml but no TLS keystore is configured. Acceptable for local development. A production server.xml should add a <keyStore> element or enable Liberty's auto-generated dev certificate via ssl-1.0 feature.
Jakarta EE 9+ migration pathFutureThis migration targets Java EE 8 / Servlet 4.0, which retains the javax.* namespace. A further step to Jakarta EE 10 / Servlet 6.0 would rename all javax.servlet.* imports to jakarta.servlet.* — a mechanical find-and-replace with no logic changes required in this codebase.
