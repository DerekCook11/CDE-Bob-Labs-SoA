1. Executive Summary

The ISS Travel App has been successfully migrated from IBM WebSphere Application Server 9 / Java 8 / Java EE 7 to Open Liberty 26.0.0.9 / Java 17 / Java EE 8 (Servlet 4.0). The migration removed all proprietary WebSphere runtime dependencies, eliminated the unnecessary EAR packaging layer, and retained 100% of the original business logic, REST API contracts, sample data, and browser UI without modification.

10. Remaining Risks and Follow-up Items

ItemSeverityDetail
In-memory data store Informational TravelRepository uses a static List. POST-created records are lost on server restart. Identical behaviour to the legacy version — no regression. Future: add JPA/JDBC persistence.
javax.* → jakarta.* namespace Low The migration targets Servlet 4.0 (javax.servlet.*). Upgrading to Liberty's servlet-5.0 or servlet-6.0 feature later requires renaming all javax.servlet imports to jakarta.servlet — a mechanical find-and-replace, no logic changes needed.
Hand-rolled JSON serializer Low JsonUtil uses string concatenation and regex. Functionally sufficient for the current flat model but fragile for Unicode edge cases or nested objects. Recommend replacing with Jackson or JSON-B if the data model grows.
JUnit 4 test framework Low JUnit 4.13.2 is compatible with Java 17. Upgrading to JUnit 5 (Jupiter) is recommended for new tests.
Empty legacy/ package directory Cosmetic The com.ibm.demo.isstravel.legacy/ source directory is empty after deleting the three WebSphere classes. Can be removed with rmdir without any build impact.
No authentication enforcement Medium (future) The legacy ibm-web-bnd.xml security binding is removed. No servlet enforces @RolesAllowed or URL-pattern constraints. APIs are open. Authentication must be added before non-localhost deployment.
maven-compiler-plugin 3.8.1 Low Version 3.8.1 works correctly for <release>17</release> but predates stabilised support. Recommend upgrading to 3.13+ on next dependency refresh cycle.
